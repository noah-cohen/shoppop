# ShopPop

אתר בעברית וב־RTL לאיתור מכירות חד־פעמיות ומתמשכות, עם ניהול למנהלת, אזור אישי בכניסה באמצעות מייל וסיסמה ומסד נתונים מקומי ב־SQLite או חיצוני ב־PostgreSQL.

## הפעלה

נדרשת Node.js גרסה 24 ומעלה. בהתקנה ראשונה מתקינים את התלויות מהקובץ הנעול; ההפעלה המקומית ממשיכה להשתמש במסד SQLite הקיים כל עוד `DATABASE_URL` אינו מוגדר.

```powershell
npm ci
npm start
```

פותחים `http://127.0.0.1:3000`.

קישור הניהול אינו מוצג למבקרים. מנהלת האתר נכנסת דרך הכתובת הישירה `http://127.0.0.1:3000/#admin` בהפעלה מקומית, או באמצעות הוספת `/#admin` לכתובת האתר לאחר הפרסום. יש לשמור את כתובת הניהול ואת הסיסמה באופן פרטי.

בהפעלה הראשונה נוצרת סיסמת ניהול אקראית שמודפסת **במסוף בלבד**. יש לשמור אותה במקום פרטי. אפשר במקום זאת להגדיר סיסמה של לפחות 12 תווים לפני ההפעלה הראשונה:

```powershell
$env:ADMIN_PASSWORD = 'replace-with-a-unique-long-password'
npm start
```

משתנה זה משמש רק ביצירת מסד חדש; הוא אינו מחליף סיסמה קיימת. סיסמה קיימת מחליפים מתוך מסך הניהול. אין לכתוב סיסמאות בקוד או לשתף את פלט ההפעלה.

## נתוני הדגמה — אופציונלי

האתר מתחיל ריק. לטעינת נתונים פיקטיביים, כשהמסד עדיין ריק:

```powershell
npm run seed
```

כל הרשומות לדוגמה מסומנות ״דוגמה״, אינן מייצגות חנויות או אירועים אמיתיים, ונוצרות ביחס לתאריך הטעינה בישראל. הפקודה מסרבת לשנות מסד עם רשומות קיימות. אין להציג את נתוני הדוגמה כפרסום אמיתי. אפשר למחוק אותם ממסך הניהול: קודם מכירות, אחר כך חנויות ואולמות.

## מה כלול

- מועדפים עם סנכרון אופציונלי: ללא כניסה, כפתורי הלב נשמרים ב־localStorage בדפדפן. כניסה לאזור האישי באמצעות מייל וסיסמה ממזגת את המועדפים המקומיים עם המועדפים שבחשבון ומסנכרנת אותם בין מכשירים. לשונית ״המועדפים שלי״ מציגה מכירות שמורות להיום ולהמשך, חנויות שמורות ומכירות שכבר היו בנפרד. ביטולים ודחיות מוצגים עם הסטטוס הקיים; פריטים שהוסרו מהאתר מסומנים כלא זמינים וניתן להסירם מהמועדפים.
- האזור האישי כולל הרשמה וכניסה באמצעות מייל ייחודי וסיסמה. כתובת המייל אינה מאומתת באמצעות הודעה, והאתר אינו שולח מיילים. סיסמאות נשמרות רק כגיבוב `scrypt` מומלח. בעת ההרשמה נשמרים שם פרטי, שם משפחה, תאריך לידה, מגדר ועיר.
- כפתור עין בשדות הסיסמה מאפשר להציג ולהסתיר את ההקלדה, כולל אימות הסיסמה בהרשמה ושדות הניהול. הסיסמאות מוסתרות כברירת מחדל; ההצגה אינה משנה את הערך או שולחת את הטופס.
- כל משתמש יכול לבחור בנפרד רשימות עדכונים לפי העיר שלו, לפי החנויות או המכירות שסומנו כמועדפות, מכירות אאוטלט ורשימת מכירות יומית. הסכמה לתוכן פרסומי היא אופציונלית ונפרדת. ההעדפות ניתנות לעריכה ומופיעות למנהלת בלשונית ״רשימות עדכונים״, מסווגות לפי הבחירה; אין שליחת מיילים אוטומטית.
- ״בחרי הכול״ בהרשמה ובאזור האישי מסמן או מנקה את כל רשימות העדכונים, ללא שינוי בהסכמה הנפרדת לפרסומות. כפתור שמירת השינויים באזור האישי פעיל רק כשהערכים שונים מהפרטים שהוצגו; החזרת כל הערכים לקדמותם משביתה אותו שוב. אחרי התחברות או הרשמה מוצגת חלונית הצלחה שניתן לסגור.

- סטטוס חי לפי שעון ישראל בכרטיסים, בפרטים ובניהול: נפתחת היום בשעה מסוימת, מתקיימת עכשיו, הסתיימה להיום או הסתיימה. התוויות מתעדכנות בכל 30 שניות לפי הנתונים שנטענו בעמוד; שינויים שנשמרו במכשיר אחר מופיעים לאחר רענון. בתאי הלוח הסטטוס החי מוצג ביום הנוכחי בלבד.
- בעריכת מכירה אפשר לסמן ביטול, דחייה ללא מועד חדש או שינוי פרטים, עם הודעת הסבר חובה. הביטול/הדחייה וההודעה מוצגים בכל התצוגות, כולל הלוח ודף החנות; המועדים המקוריים נשמרים לאזהרת מבקרות, ואין קישור ניווט למכירה לא פעילה. מכירות אלה אינן נספרות במונה ״מתקיימות היום״ ואינן משתתפות בהצעת איחוד חפיפות. בדחייה לא מוצעת הוספה ליומן; בביטול מיוצא אירוע עם `STATUS:CANCELLED`. קובץ מיובא אינו מבטיח עדכון אוטומטי ביומן חיצוני.
- כפתור ״שכפול לתאריכים חדשים״ בניהול מעתיק פרטים, משתתפות ומודעות למכירה חדשה. התאריכים נמחקים והסטטוס חוזר למתוכננת; חובה לבחור תאריכים לפני שמירה. המכירה המקורית אינה משתנה. הודעות שינוי נשמרות גם כשמאחדים מכירות פעילות.
- קישור ״בעלות חנות? שלחו מכירה לפרסום״ בתחתית האתר פותח טופס ציבורי ללא הרשמה: פרטי קשר, שמות חנויות, מיקום, תאריכים ושעות, תיאור, קטגוריות, קהלי יעד ומודעה אופציונלית. הבקשה נשמרת פרטית במסד, ללא פרסום חנות, אולם או מכירה. פרטי הקשר אינם מועתקים לפרסום הציבורי.
- בניהול נוספה לשונית ״בקשות לפרסום״ עם מונה ממתינות והיסטוריית אישורים ודחיות. אפשר לבחור חנויות ואולם קיימים או ליצור את החסרים מתוך הבקשה, ולערוך טיוטת מכירה רגילה לפני ״אישור ופרסום המכירה״. יצירת חנות או אולם היא פעולה מפורשת שמפרסמת את הרשומה בלבד; המכירה עדיין ממתינה לאישור. האישור ויצירת המכירה נשמרים בעסקה אחת ומוגנים מפרסום כפול. בקשה חופפת מאושרת בנפרד לאחר אזהרה; איחוד אפשרי בעריכת המכירה אחרי הפרסום.
- מודעה מצורפת נשארת פרטית עד לשימוש בה במכירה שפורסמה. הכנת טיוטה אינה מפרסמת מודעה, ואינה מסמנת בקשה כמאושרת. שליחה ציבורית מוגבלת ל־5 ניסיונות בשעה לכתובת IP, כולל בקשות לא תקינות; מאחורי שרת מתווך ההגבלה חלה על כתובתו. זוהי הגנה בסיסית ולא תחליף לסינון ספאם בתשתית ציבורית. טרם נוספו הודעות דוא״ל או SMS אוטומטיות לשולחות.
- בלשונית ״מכירות״ בניהול אפשר לשלב סינון לפי מועד, חנות (כולל השתתפות במכירה משותפת), עיר ואולם. ״מכירות קודמות״ הן מכירות שכל תאריכיהן לפני היום בישראל; ״היום ומכירות עתידיות״ כוללות מכירה שיש לה לפחות יום אחד מהיום והלאה, גם אם התחילה בעבר. גם ביטולים ודחיות נכללים לפי התאריכים השמורים. בחירת עיר מצמצמת את רשימת האולמות ומנקה אולם מעיר אחרת. המסננים נשמרים במעבר בין לשוניות הניהול ובעריכת רשומה, אינם משפיעים על הסינון הציבורי וניתנים לניקוי בכפתור אחד.
- קישור ״יצירת קשר״ בתפריט העליון ובתחתית האתר פותח טופס ציבורי ללא הרשמה: שם, נושא, הודעה עד 4,000 תווים ודוא״ל או טלפון (לפחות אחד נדרש). ההודעות ופרטי הקשר נשמרים פרטיים במסד ואינם נכללים בנתונים הציבוריים. בלשונית ״הודעות״ בניהול מוצג מונה חדשות, עם פתיחה, סימון אוטומטי כנקראה, אפשרות לסמן כלא נקראה וכפתור רענון לקבלת פניות חדשות. המועד מוצג לפי שעון ישראל. אין שליחה למייל או מענה אוטומטי, ויש לחזור לפונה באופן עצמאי לפי פרטי הקשר. הטופס מוגבל בנפרד ל־5 ניסיונות בשעה לכתובת IP, כולל ניסיונות לא תקינים, ועד 32KB לבקשה. ההגבלה בזיכרון ומתאפסת בהפעלת השרת; מאחורי מתווך היא חלה על כתובתו ואינה תחליף להגנות ספאם בתשתית. ההודעות נכללות בגיבוי מסד הנתונים; יש לשמור את הגיבוי במקום פרטי.
- מכירות היום לפי התאריך בישראל, בכרטיסים, עם חיפוש וסינון עיר/קטגוריה/אולם.
- תצוגת תאריכים אחידה: יום בשבוע, תאריך עברי באותיות ותאריך לועזי מלא בכרטיסים, בפרטים, בחלוניות ובניהול, כולל תצוגה מתעדכנת ליד שדות בחירת תאריך. בתאי הלוח מופיעים היום הלועזי והיום והחודש העבריים; התאריך המלא זמין בתיאור הנגיש ובחלונית. שמות הימים הם ״יום ראשון״ וכו׳, ולכל תאריך שבת מוצגת התווית ״מוצאי שבת״, ללא תלות בשעת המכירה. ההמרה העברית היא לפי יום התאריך הנבחר, ללא חישוב שקיעה או שינוי שעות הפעילות.
- לוח שנה חודשי וחלונית לכל יום עם סינון עצמאי. בכל כניסה לטאב מוצג החודש הנוכחי לפי שעון ישראל, והיום מסומן במסגרת פוקסיה, רקע מובחן ותווית ״היום״, ללא פתיחת חלונית אוטומטית. מעבר בין חודשים וסינון בתוך הלוח אינם מחזירים את החודש לאחור. כל מכירה מוצגת בכל יום פעילות שלה, ללא תווית ״רב־יומית״. כל המכירות מוצגות גם בנייד, ולחיצה על התאריך פותחת את פירוט היום.
- בלוח השנה ובחלונית היום ניתן לסנן גם לפי חנות, מתוך רשימה ממוינת עם חיפוש. הסינון כולל מכירות של החנות לבדה ומכירות משותפות שבהן היא משתתפת, ומשתלב עם יתר המסננים ובכל תצוגות הלוח. סינון חלונית היום אינו משנה את הסינון הראשי; בחירת החנות נשמרת בלוח בעת מעבר לתצוגה אחרת, ואינה מסננת באופן סמוי את טאב היום או את מדריך החנויות.
- קטגוריות המכירה כוללות גם את קטגוריות החנויות המשתתפות.
- קטגוריות הבחירה כוללות בגדי ילדים, בגדי נערות, בגדי תינוקות, נעלי נשים ושונות, ללא כפילויות. הסינון הציבורי מציג את כל קטגוריות הבחירה לצד ערכים קיימים.
- לכל מכירה ניתן לבחור כמה קהלי יעד: גברים, נשים, בחורים, בחורות, ילדים, ילדות, תינוקות (בנים), תינוקות (בנות) ולכל המשפחה. הבחירה אופציונלית, נשמרת בעריכה ובמסד הנתונים, מוצגת בכרטיסים ובפרטי המכירה, נכללת בחיפוש החופשי ובהוספה ליומן. מכירות ישנות ללא קהל יעד ממשיכות לפעול ללא שינוי.
- רשימת חנויות ודף חנות עם קטלוג, אתר, טלפון, כתובות ושעות קבועות אופציונליות. פתיחת חנות מתחילה בראש העמוד, גם לאחר גלילה ברשימת החנויות או פתיחה מתוך פרטי מכירה.
- בתצוגות הציבוריות מוצג לוגו במקום שם החנות אם הועלה, ואחרת השם בלבד: בכרטיסי המכירה, בדף החנות, בכותרת חלונית המכירה המשותפת ובחנויות המשתתפות. שם החנות נשאר זמין בטקסט החלופי של התמונה ובשמות הנגישים. בכרטיסי מדריך החנויות מוצג גם שם החנות בשורה נפרדת מתחת ללוגו, במשקל רגיל, לצד מספר המכירות הקרובות (כולל היום). ללא לוגו השם מוצג פעם אחת, בלי תמונת תחליף.
- ללוגואים יש מידות קבועות ללא כיווץ לפי תמונה או מספר חנויות: גדול 180×100 פיקסלים בכותרת מכירה בודדת, בכרטיס חנות ובכותרת דף חנות; קטן 64×40 פיקסלים במשתתפות במכירה משותפת, בפרטים ובתצוגת העריכה. בלוח השנה בלבד המידה היא 64×40 במחשב, 32×28 ברוחב מסך של עד 1,000 פיקסלים ו־16×24 עד 650 פיקסלים, כדי שכל השבוע ייכנס בנייד. התמונות מותאמות בתוך המידות הללו בפרופורציות המקוריות וללא חיתוך, רקע או מסגרת נוספת על התמונה עצמה. מקום לתגית אאוטלט או לכפתור הסגירה נוצר באמצעות שבירת שורה ולא באמצעות הקטנת הלוגו.
- מונה המכירות המתקיימות היום מוצג כמספר רגיל ללא אפס מוביל, למשל 3 ולא 03.
- בכרטיסי המכירות יש קווים דקים בין אזורי המידע: מיקום, שעות, קהל יעד וקטגוריות. קהל היעד מוצג תמיד; אם לא הוגדר, נכתב ״לא צוין״ בלי להסיק אותו מהקטגוריות. בתצוגת הפתיח בשתי עמודות, המונה והכותרת ״כל המכירות״ מתחילים באותה שורת רשת; בנייד נשמרת הפריסה המדורגת.
- בכרטיס של מכירה משותפת, שם המכירה ותיאורה מופיעים מתחת לכותרת ״מכירה משותפת״ ולפני רשימת החנויות המשתתפות.
- מתחת לתיאור בכרטיס מכירה משותפת מופיעים קו מפריד דק ומלבני החנויות, ללא כותרת נוספת. לכל חנות יש אותה מסגרת וריווח פנימי, בין שמוצג בה לוגו ובין שמוצג שם. הלוגו עצמו נשאר ללא רקע או מסגרת נוספת, ולוגו שמשמש ככותרת במכירה בודדת נשאר ללא מסגרת. שם החנות נשמר כטקסט חלופי ללוגו וכרמז בריחוף. רקע שנמצא בקובץ התמונה המקורי אינו מוסר.
- התפריט העליון ממורכז במחשב ובנייד. בתצוגת החנויות בלוח השנה, נקודת פוקסיה מופיעה לפני כל חנות, גם כשמוצג לוגו; שמות החנויות ללא לוגו בלבן. הכותרת ״מכירה משותפת״ בפוקסיה, ממורכזת ועם פס מתחתיה.

## שמירה וגיבוי

בהפעלה מקומית ללא `DATABASE_URL`, הנתונים נשמרים ב־SQLite בקובץ `data\calendar.sqlite`. כשמגדירים `DATABASE_URL`, הנתונים נשמרים ב־PostgreSQL (למשל Neon), ולא בדיסק הזמני של שרת האתר. גם סיסמת הניהול (מומלחת ומגובבת) וההתחברויות נשמרות באותו מסד. משך התחברות: שבעה ימים; שינוי סיסמה מבטל את כל ההתחברויות.

גם תמונות מודעות הפרסומת נשמרות במסד, בטבלה נפרדת, ונכללות באותו גיבוי. הן אינן נשלחות כחלק מרשימת המכירות אלא נטענות בנפרד בפרטי המכירה. בעת שמירה, התמונות מועלות תחילה כטיוטות ורק שמירת המכירה מקשרת ומפרסמת אותן. אם השמירה נכשלה, מוצגת שגיאה ואפשר לנסות שוב. תמונות ללא קישור למכירה אינן נגישות לציבור; טיוטות ותמונות שהוסרו ולא קושרו שוב נמחקות לאחר 24 שעות בעת העלאה נוספת או הפעלת השרת.

כדי להעביר את האתר למחשב אחר, מעבירים את קובצי הפרויקט ואת **מסד הנתונים**, ולא רק את קובצי התצוגה.

במצב SQLite בלבד, אפשר לגבות גם באמצעות עצירת השרת, העתקת **כל תיקיית `data`**, והפעלה מחדש. אין להסתפק בהעתקת קובץ SQLite בודד כאשר השרת פועל, מכיוון שיש קובצי WAL נלווים. שמרו את הגיבוי במקום מוגן; הוא מכיל גם נתוני התחברות. לייצוא עקבי ללא עצירת השרת, ב־SQLite או ב־PostgreSQL, ראו את פקודת הגיבוי בהמשך.

אפשר לבחור תיקיית נתונים אחרת, ורצוי בהפעלה אמיתית תיקייה מקומית שאינה מסונכרנת בזמן אמת ב־OneDrive:

```powershell
$env:DATA_DIR = 'C:\sale-calendar-data'
npm start
```

נתיב זה חייב להישאר קבוע בין הפעלות. שינויו למסלול ריק ייצור מסד חדש.

## פרסום באינטרנט

זו אפליקציית שרת, לא אתר סטטי בלבד. ההפעלה המקומית אינה מפרסמת את האתר באינטרנט.

לפני פרסום אמיתי יש לבחור אירוח שמריץ Node.js 24 ולהשתמש במסד PostgreSQL חיצוני, או לחלופין בדיסק קבוע למסד SQLite. אין לשמור SQLite בדיסק זמני או להעלות מסד, גיבוי או קובץ סביבה לתיקייה ציבורית. גרסה זו מיועדת לתהליך שרת יחיד ולמנהלת אחת.

משתני הסביבה:

| משתנה | משמעות |
|---|---|
| `PORT` | ברירת מחדל 3000 |
| `HOST` | ברירת מחדל `127.0.0.1`; מאחורי proxy/באירוח משתמשים בדרך כלל ב־`0.0.0.0` |
| `DATA_DIR` | תיקיית דיסק מתמיד |
| `DATABASE_URL` | כתובת PostgreSQL פרטית; אם מוגדרת אין שימוש במסד SQLite המקומי. בחיבור מרוחק נאכף TLS עם אימות תעודה |
| `ADMIN_PASSWORD` | סיסמה ראשונית בלבד; לפחות 12 תווים |
| `COOKIE_SECURE` | יש להגדיר `true` באירוח עם HTTPS; לא בהפעלה מקומית ב־HTTP |
| `BACKUP_DIR` | תיקייה פרטית לייצוא גיבויים; ברירת המחדל `backups` |

יש להגדיר דומיין ו־HTTPS דרך ספק האירוח או reverse proxy, לשמור את Host המקורי בהעברה לשרת, להגביל גישה ישירה לשרת מאחורי ה־proxy, לקבוע גיבויים, ולהחליף את הסיסמה הראשונית. אין מנגנון שחזור סיסמה בדוא״ל בגרסה זו. יש לשמור את סיסמת המנהלת במנהל סיסמאות.

הגרסה כוללת עוגיות HttpOnly/SameSite, בדיקת Origin לפעולות כתיבה, הגבלת ניסיונות כניסה לפי כתובת החיבור, אימות נתונים בצד השרת, הגבלות גודל בקשה ו־CSP. מאחורי proxy הגבלת הכניסה המקומית עשויה להיות משותפת למשתמשים; באירוח ציבורי יש להוסיף הגבלת ניסיונות בקצה לפי הגדרת ספק האירוח. אלה אינם תחליף לבדיקת מוכנות לפרודקשן ולבדיקות נגישות מלאות.

### התחלה בחינם: Render + Render PostgreSQL

הקוד מוכן למסלול זה, אך הוא **אינו יוצר חשבונות ואינו מפרסם את האתר אוטומטית**. הבעלים צריכים לפתוח חשבונות, לבחור במפורש במסלולים ולהגדיר סודות באופן פרטי. אין להעביר מפתחות או כתובות חיבור בצ׳אט.

1. במחשב המקומי מעתיקים את תבנית הסביבה:

   ```powershell
   Copy-Item .env.example .env
   ```

   עורכים את `.env` **פרטית** בעורך. אין להדביק סודות בפקודות הנשמרות בהיסטוריה. `npm start`, כלי ההעברה וכלי הגיבוי קוראים את הקובץ; משתני סביבה שכבר הוגדרו גוברים עליו. חיבור למסד מרוחק דורש אימות תעודת TLS; אין להשתמש בהשבתת אימות.
2. מעלים את **קוד המקור בלבד** למאגר Git פרטי בחשבון שבבעלותכם, מחברים אותו ל־[Render](https://render.com/docs/blueprint-spec), ובוחרים Blueprint המבוסס על `render.yaml`. לפני העלאה בודקים ש־`.env`, תיקיית `data`, תיקיית `backups` וקובצי SQLite אינם נכללים במאגר.
3. ה־Blueprint יוצר שירות Web ומסד Render PostgreSQL חינמי ומחבר ביניהם. בשדה הסודי מגדירים `ADMIN_PASSWORD`. אין לשמור אותו בקוד. מסד Render Free פג ונמחק אחרי 30 יום; לפני תאריך התפוגה נכנסים למסד ב־Render Dashboard ומשנים את ה־compute plan למסלול בתשלום כדי לשמור אותו ואת הנתונים.
4. אם רוצים להעביר את הנתונים המקומיים הקיימים, מעתיקים באופן פרטי את כתובת החיבור החיצונית של מסד Render אל `DATABASE_URL` ב־`.env`, מפסיקים לערוך נתונים במחשב ומריצים:

   ```powershell
   npm run migrate:postgres
   ```

   הכלי קורא תמונת מצב עקבית של SQLite במצב קריאה בלבד, שומר גיבוי פרטי בתיקיית `backups`, ומייבא למסד Neon **רק אם כל טבלאות היעד ריקות**. הוא מעביר חנויות, אולמות, מכירות, קישורים, תמונות, בקשות, הודעות, סיסמה מגובבת והתחברויות. התוכן מאומת במלואו לפני אישור העסקה; כשל גורר ביטול. מזהי הרשומות נשמרים, ומוני המזהים מותאמים להוספות חדשות. המקור המקומי לא משתנה. אין סנכרון אוטומטי של שינויים שנעשו ב־SQLite לאחר ההעברה.
5. לאחר אישור ההעברה, פורסים מחדש ובודקים שהנתונים מופיעים ושהכניסה לניהול ולחשבון עובדת. נשמרת סיסמת המנהלת הקיימת; `ADMIN_PASSWORD` אינו מחליף אותה.
6. Render מקצה כתובת HTTPS מסוג `https://<service>.onrender.com`. בודקים פתיחת האתר, הרשמה, כניסה, רשימות העדכונים בניהול, סנכרון מועדפים בשני דפדפנים, מסננים, שמירה וטופס קשר, ולאחר פריסה מחדש מוודאים שהנתונים נשארו.

**מגבלות:** Render Free נרדם אחרי חוסר פעילות, ולכן כניסה ראשונה יכולה להתעכב. מסד Render PostgreSQL החינמי נמחק אחרי 30 יום אם לא משדרגים אותו. יש לבדוק את המכסות והמחירים העדכניים לפני השדרוג. ללא אימות מייל אין אפשרות לוודא שהכתובת שהוזנה שייכת לנרשם, ואין שחזור סיסמה אוטומטי.

### ייצוא גיבוי ושחזור למסד PostgreSQL ריק

```powershell
npm run backup
```

הפקודה יוצרת קובץ JSON פרטי עם תמונת מצב עקבית, כולל תמונות מקודדות, פרטי קשר ונתוני התחברות. היא משתמשת ב־`DATABASE_URL` אם הוגדר, או במסד SQLite המקומי הקיים. יש להריצה **מהמחשב המקומי** ולשמור עותק במקום פרטי נפרד; קובץ שנשמר בדיסק Render החינמי יימחק. זהו כלי גיבוי ידני, לא שירות גיבוי אוטומטי, ולא תחליף למדיניות שחזור של ספק המסד. הגיבוי מכיל מידע אישי ורגיש, לרבות כתובות מייל, פרופילים, העדפות דיוור וגיבובי סיסמאות, ולכן יש לשמור אותו מוצפן ובגישה מוגבלת.

כדי לשחזר, מגדירים באופן פרטי `DATABASE_URL` למסד או branch חדש וריק, ואז:

```powershell
npm run migrate:postgres -- --backup "C:\private-backups\calendar-backup.json"
```

השחזור מסרב לדרוס מסד לא ריק. אם האתר כבר הופעל ויצר מנהלת, משתמשים במסד חדש וריק ולא מוחקים נתונים כדי לעקוף את ההגנה.

## עדכון רשימת היישובים

הנתונים מגיעים מה[מאגר הממשלתי ״רשימת ישובים בישראל״](https://data.gov.il/dataset/citiesandsettelments/resource/5c78e9fa-c2e2-4771-93ff-7f400a12f7ba), ומוצלבים לפי סמל יישוב עם [קובץ היישובים של הלמ״ס לשנת 2023](https://data.gov.il/dataset/localities-in-israel/resource/d47a54ff-87f0-44b3-b33a-f284c0c38e5a). הקובץ `public\cities.json` כולל מקורות, מועד הורדה, שנת סיווג ושמות שהוסרו או שלא סווגו. האתר משתמש בעותק המקומי ואינו תלוי בזמינות המאגרים בזמן השימוש. העדכון נכשל במפורש אם נתוני אחד המקורות חלקיים או שסיווג חדש אינו מוכר, ומשאיר את הקובץ הקודם. לעדכון יזום:

```powershell
npm run update-cities
```

העדכון מאמת שכל הרשומות הורדו לפני החלפת הקובץ. רשימות הקטגוריות ואמצעי התשלום נמצאות ב־`public\options.js`. לא בוצעה הסבה כפויה של רשומות קיימות לשמות החדשים.

## רעיונות להמשך

1. **מועדפים ותזכורות:** מעקב אחרי חנות או קטגוריה ותזכורת לפני מכירה, בהסכמה מפורשת.
2. **מפת מכירות:** מכירות בקרבת מיקום שנבחר, מרחק וזמן נסיעה.
3. **ביטול ועדכונים:** סימון ״נדחה״/״בוטל״ במקום מחיקה, ותיעוד מועד אימות הפרטים.
4. **הצעת מכירה לאישור:** טופס לבעלי חנויות שנכנס לתור אישור שלך, בלי פרסום אוטומטי.
5. **פרטים שימושיים:** נגישות, חניה, תחבורה ציבורית וטווח מחירים.
6. **גלריית תמונות למכירה:** בנוסף ללוגו ולמודעה לכל חנות שכבר נתמכים, אפשר להוסיף כמה תמונות מוצר.
7. **מניעת כפילויות ותצוגה מקדימה:** התראה על מכירות דומות ופרסום טיוטה רק אחרי אישור.

הרעיונות האלה אינם ממומשים כרגע; ההתמקדות בגרסה הנוכחית היא בתכנון ביקור ובניהול אמין של הנתונים.
